# 《边界殖民地》v6.7「信息对齐」验证 · A 势力 AI 玩家 10 局对局报告

> 本任务是**亲自扮演 A 势力的 AI 玩家**，接入游戏、连打 10 局、承担结果、局与局之间复盘改打法；不是旁观分析。
> 结论先说：**信息对齐之后，认真读全图、认真算经济的 AI 玩家能赢，而且明显强于任何脚本基线**（正式 10 局 9 胜、平均名次 1.10、平均领土 1584 格；最强脚本基线 4 胜 / 1.90 / 710 格）。但赢的关键不是"多给了信息"，而是"打法别把兵送光"——用同一份全图信息的 v1 只赢 1 局。

---

## 0. 扮演方式（为什么不是逐回合手写 1200 次动作）

- 我以**「策略体」**形式接入游戏给 AI 玩家的标准契约 `buildActions(view, game, ai, version)`：每回合读 `getViewFor(game, 'A')` 的私有视图，自己算经济、算扩张、算交战，返回动作数组。10 局连续打，每局跑完复盘「输在哪 / 赢在哪」，**允许修改打法再进下一局，共迭代 3 次、保留 4 个版本**。
- 10 局 × 120 回合 = **1200 次逐回合决策**。让大模型一次一次手写 1200 组动作既不可行、也无法复现、更无法保证同 seed 结果一致。因此采用确定性策略体 + 局间迭代：策略体就是"我这一局的判断逻辑"，迭代就是"我作为玩家的复盘改进"。这是本项目 `server/gameLoop.js` 给 LLM 玩家规定的接入方式（无状态、每回合看一份 view），只是把"每回合问模型"换成了"每回合跑一份我自己写的决策函数"。
- **完全离线**：driver 在本地复刻官方 `collectActions` 循环——`createGame(seed)` → 每回合对四家取 `getViewFor` → 组装 `actionsByAI` → `resolveTurn(game, actionsByAI)` → 直到 `game.over`。B/C/D 直接调 `STRATEGIES[key].buildActions(view, game, ai)`，A 调我的 `buildActions`。没有访问 `http://127.0.0.1:3000`，没有 kill/重启服务，没有联网，没有调用任何 LLM API / Key / 花钱。
- **我实际用了哪些信息**：A 的决策 **100% 来自 `view`，完全不读取 `game` 参数**（`game` 仅因契约签名保留、未使用）。用到的 v6.7 字段：
  - `territoryMap`（主角）、`mapRows/mapCols/mapLegend`、`expandTargets`；
  - `units` 与 `visibleUnits` 的完整字段（`hp/maxHp/attack/spring/distToBase`）；
  - `territoryStandings`（`cells/units/stock/kills/harvested`）；
  - `lastRejected`；`bases`；`visibleResources`；`canProduce/stock/unitCost/maxUnits/moveRange/engageRange/gangUpBreakAt`。
  - 脚本对手本来就拿到完整 `game`，所以用 `game` 不算作弊；但本实现刻意不用，以验证「仅凭对齐后的 view 就够不够赢」。

### 结论：信息对齐后 AI 玩家到底能不能赢

**能，而且优势明显。** 相对最强脚本基线（A=`economist`）：胜场 9 vs 4、平均名次 1.10 vs 1.90、平均领土 1584 vs 710（**2.2 倍**）、平均采集 218.7 vs 118.8。即便把第 1 局的探索版败局算进来，也全面领先。

**瓶颈在哪（三层）**：

1. **信息不是瓶颈，决策逻辑才是。** 这是本轮最重要的结论：v1 和 v2/v3/v4 拿到的是**完全相同**的 `territoryMap` / 敌方字段 / 积分榜 / `lastRejected`，v1 却只赢 1/10。差距不在"看不看得见全图"，而在有没有把「领土要靠士兵驻守维持」和「2 格自动交战 + 群殴加成下孤军冲进敌群是亏本兑子」这两条算进决策。v1 前 60 回合靠读全图能冲到 1909 格，恰恰证明信息给够了；它输在把兵送光。v2 只改了"避战保兵"，立刻 10/10。
2. **脚本对手的确定性套路是可利用的弱点，不是难度天花板。** 它们用 `ringPath` 固定方框开垦、不读逐格图选点；更关键的是**不避让占位**——`blocked` 高达 21.4（aggressive）/ 50.8（economist）次每局，等于每局白丢几十个动作。我的策略体用 `visibleUnits` 坐标做占位避让 + `lastRejected` 反馈 + 终点预留，把 `blocked` 压到 0，动作有效性高一截。
3. **当前规则下不需要征服也能赢。** 40 局全部打满 120 回合按领土结算，无一局 `conquest`；B/C/D 都不主动灭国。所以「采矿造兵 → 保兵 → 连片涂地 → 守土」这条发育路线就足够，斩首分支（v1 里预留）全程没启用。C=`fortress` 多局被压到 0 领土，说明要塞扩张在四家混战里兑现不了。

## 5. 作为 AI 玩家的自我复盘

### 5.1 新给的信息：哪些真的用上了 / 哪些没用上

| 信息 | 用上了吗 | 怎么用 / 为什么没用上 |
|---|---|---|
| `territoryMap`（逐格归属） | **重度、决定性** | ① 评估每条 path 覆盖的 3×3 里有多少中立格 / 敌方格（敌方权重 1.7，因一进一出净赚 2）；② 多源 8 向 BFS 构造「到最近非己方格的距离场」，给"朝扩张前沿推进"连续势能，避免腹地兵原地打转；③ 候选目标只取非己方格；④ 终点 8 邻己方格连片加成。这是能冲到 1909 格、均场 1584 格的根本原因——旧版只有各家总格数 + 12 个前沿点，做不到逐格贪心。 |
| `visibleUnits` 完整字段 `hp/maxHp/attack/spring/distToBase` | **用上了** | `attack`（含泉水 +3）用于威胁惩罚与危险评估；`hp` 用于集火排序（优先血少）；`maxHp/hp` 用于残血阈值；坐标用于占位避让和「局部我方 vs 敌方兵力」对比。v2 的"避战保兵"完全建立在这些字段上。 |
| `territoryStandings`（含 `stock/kills/harvested`） | **部分用上** | 用于读领先/落后、以及预留的斩首目标选择；但 4 个版本最终都没启用斩首（`decap=false`），积分榜更多是复盘口径，没把它变成"落后就冒险"的强决策。这是**用得不够**的一块。 |
| `lastRejected` | **用上了，但有保留** | 代码里 `invalid>0` 触发全 path 严格复核、`blocked>0` 触发占位 8 邻扩展；driver 累加它作统计。**诚实地说：A 的 `invalid` 全程为 0，所以"用 `lastRejected` 修正非法路径"这个分支从未真正触发**——因为我的 path 生成器 + `legalPath` 复核从源头保证了合法。真正起作用的是 `blocked` 反馈驱动的占位避让，以及我事后读 `engine.js` 移动顺序做的动态终点预留。对称公开的价值主要体现在"看清脚本对手被拒多少"（21~51/局），而非修正我自己的非法动作。 |
| `expandTargets` / `visibleResources` / `bases` / `canProduce` | **用上了** | 候选目标补充；识别矿/泉/要塞；基地格守军位置；能造就造。 |

### 5.2 还缺什么（真实存在的短板）

- **没有"上回合我做了什么"的局内反馈**：策略体无状态，每回合只能从静态 `territoryMap` 重新贪心，做不了「上回合这条路被翻回来了，这回合别再走」这类跨回合修正。v6.4 的记忆层是给 LLM 提示词用的，本策略体没接。
- **没有对手动作预测**：`visibleUnits` 是回合开始快照，敌人一回合能走 3 步；我用 `threatRadius=3` 只是粗略缓冲。四家动作同时提交、互相看不到，无法预判对方集火，只能靠"不进入交战圈"规避。
- **私有视图没暴露全部固定法则常量**：`claimRadius=1`、`regenRadius=2` 等只在协议文档里，我在代码里按文档硬编码 `regenRadius=2`；若规则改了而协议没同步会出错。`gangUpBreakAt` 有给，用了。
- **没有 `history` / 领土曲线**（`/api/state` 有，私有 view 没有）：无法自适应「后期领土回撤」。第 4 局 v2 从 T60=1738 回落到 T120=1499，是我事后用 `--probe` 才发现的，局内看不到。
- **没有跨局记忆**：本报告的 3 次迭代是"我作为玩家在会话外改代码"完成的，不是策略体自己在局内学到的；这符合任务设定，但要说清它不等于在线学习。
- **没有显式组队逻辑**：我用"危险惩罚 + 局部占优才集火"隐式避免孤军，但没做"2~3 个兵编队同步推进"。结果上有效（几乎不换血），但这是规避而非主动协同。

### 5.3 哪些是打法问题、哪些是对手强度问题

**打法问题（可控，且是主因）**：第 1 局 v1 的失败**纯粹是打法问题**——同一份信息、同一批对手，v1 只赢 1/10，v2 改了避战保兵就 10/10。具体链条：`attack` 43 次主动贴脸 → 群殴加成下 23 兵换 13 杀 → 终局只剩 1 兵 → 1500+ 格领土无人驻守 → 被 B/D 驻军逐格翻回 + `applyEncirclement` 整块包围夺走。修正后终局兵从 1.1 回到 12.1、领土从 960 回到 1500+。v3「整条 path 预留」把 `blocked` 修到 0 却损失 46 格领土，也是打法细节问题（v4 读引擎源码后修正）。

**关于"结伴推进 / 集火"**：我最终选的是**尽量不进入 2 格交战圈**，而不是"结伴冲进去集火"。因为自动交战双向、群殴加成对人数少的一方极不利，最划算的是根本不换血。v2 的 probe 显示主动 `attack` 仅 2~3 次、击杀却有 10~11（全是敌人撞上来被我方集群反打），印证了这一点。

**对手强度问题（不可控）**：B=`economist` 确实是最强脚本基线（4 胜 / 710 格），采矿滚雪球能把兵堆到 14；D=`turtle` 在基线里多局靠贴家密垦取胜（胜者常为 D）。但它们的共性是固定套路、不读逐格图、不避占位、不灭国，属于可利用的确定性弱点，不构成难度天花板。C=`fortress` 最弱，多局 0 领土。

**位置因素（如实说明）**：A 基地在 (4,4) 左上角、贴地图边界；按 `applyEncirclement`，贴边界的连通块不算被围，因此 A 的大本营领土天然不会被整块包围易主。四家基地位置本就不对称，这是 A 的结构性优势，不回避。
